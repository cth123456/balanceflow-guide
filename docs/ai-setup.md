# AI 配置教程

[返回首页](../README.md) · [完整使用手册](user-guide.md) · [训练库教程](exercise-library-conversion.md)

适用界面：设置页中有“AI 接口”“接口平台”“保存密钥并自动配置”的版本。界面若有差异，先在“设置 → 关于衡动”核对已安装版本。

## 配置前先分清四件事

| 名称 | 它是什么 | 不能拿什么代替 |
| --- | --- | --- |
| 服务商 API 账户 | 在模型接口平台开通的开发者账户 | 不能仅凭聊天网站能登录就认为有 API 权限 |
| API 密钥 | 服务商控制台创建的接口凭证 | 不是邮箱密码、验证码或网页登录 Cookie |
| API 基础地址 | 发请求的 HTTPS 服务入口 | 不是聊天页面、控制台首页或模型介绍页 |
| 模型 ID | 服务商实际接受的模型标识 | 不是自己起的昵称，也不一定是宣传页中文名 |

衡动当前提供的是“选择平台 + 自行填写 API 密钥”，没有“登录 ChatGPT/Codex/Muse 后同步聊天”的入口。

先准备所选平台的 API 密钥、可调用的模型 ID，以及平台要求的额度或调用权限。不要把密钥发到 Issue 或聊天里让别人代填。不准备开通 AI 时，可以先使用手动记餐和基础训练记录。

## 使用内置平台预设

1. 打开衡动底部 **设置**。
2. 找到 **AI 接口**，点 **接口平台**。
3. 选择密钥所属平台。现有预设包括硅基流动、OpenAI、DeepSeek、OpenRouter，也有“自定义兼容接口”。
4. 在 **API 密钥** 栏粘贴完整密钥，不额外加引号或 `Bearer `。
5. 点 **保存密钥并自动配置**。
6. 看到“密钥已保存”后，点 **测试文字分析连接**，等结果显示。
7. 失败时查本章末尾排错表，不要同时修改所有字段。

预设会填写地址、接口格式和内置推荐模型，但不同账户的权限可能不同。**成功标准是请求真正完成，不是显示“已配置 4/4”。** 模型已下线或无权限时，需在高级设置填写平台当前可用的模型 ID。

### 从哪里取得密钥

在对应平台官方开发者控制台登录，找到 API 密钥管理入口，创建自己使用的密钥，再回衡动粘贴。平台可能只展示一次完整密钥，请按其提示保存。

| 平台 | 官方入口 | 衡动中的选择 |
| --- | --- | --- |
| OpenAI | [API Platform](https://platform.openai.com/) | OpenAI |
| 硅基流动 | [SiliconFlow 控制台](https://cloud.siliconflow.cn/) | 硅基流动 |
| DeepSeek | [DeepSeek 开放平台](https://platform.deepseek.com/) | DeepSeek |
| OpenRouter | [OpenRouter](https://openrouter.ai/) | OpenRouter |

平台界面、资费、支持地区和模型权限以平台当前说明为准。衡动不会代充值，也不附送这些平台的调用额度。

### 换平台的完整顺序

例如从 DeepSeek 换到 OpenAI：选择 OpenAI → 输入 OpenAI 密钥 → 点“替换密钥并补齐模型” → 重新测试文字、图片和录音。

不要只切平台、不换密钥。当前配置使用一份活动密钥；平台名称变化不表示凭证已换成另一家。

## 手动配置每个字段

展开 **手动修改接口与模型**。使用自建或第三方兼容服务时，先选“自定义兼容接口”。

| 字段 | 怎么填写 | 常见错误表现 |
| --- | --- | --- |
| 接口格式 | 与服务商协议一致：Responses API 或 Chat Completions 兼容接口 | 路径不存在、返回结构无法识别 |
| API 基础地址 | 服务商文档给出的 HTTPS 基础入口 | 域名错误、404、返回网页 |
| 日常分析模型 | 支持文字输入且账户有权限的完整模型 ID | 模型不存在或无权限 |
| AI 教练模型 | 长对话使用的文字模型；可留空沿用日常模型 | 复盘可用但教练不可用 |
| 图片识别模型 | 支持图片输入的模型 ID | 文字成功，餐食照片仍失败 |
| 语音识别模型 | 兼容 `/audio/transcriptions` 转写接口的模型 ID | 聊天成功，但录音转写失败 |

### 地址例子

假设服务商文档写“基础地址为 `https://your-provider.example/v1`，文字接口为 `POST /chat/completions`”，则填写：

```text
接口格式：Chat Completions 兼容接口
API 基础地址：https://your-provider.example/v1
日常分析模型：服务商给出的真实模型 ID
```

衡动自动追加 `/chat/completions`；选择 Responses API 时追加 `/responses`。末尾已包含所选协议对应路径时不会重复追加。

`.example` 是讲解占位符，不能直接连接。基础地址有的包含 `/v1`，有的不包含，照服务商文档填写；不要填控制台网址，也不要形成 `/v1/v1`。

### 三种能力不一定用同一个模型

可在同一个基础地址下分别填写文字、图片、转写模型。**这套设置共用基础地址和密钥**，不能直接把三家平台的模型拼在一起。

没有图片能力时先用文字，没有转写接口时先键盘输入。模型“支持音频”也不代表它兼容衡动使用的转写接口。

## 按顺序验证三种能力

### 1. 文字

在设置中点“测试文字分析连接”。测试会发请求，可能消耗平台额度。

成功说明这次文字请求的地址、密钥、模型和协议组合可用。失败时记下 HTTP 状态或错误文字，按下表排查。

### 2. 图片

进入 **饮食**，点右上角 AI 记餐入口，选择一张清晰单餐照片，附上“这份是我一个人吃的，已吃完”等实际说明，开始识别。

**通过标准：** 返回可以核对、编辑的食物与营养结果。成功选中照片、打开相机不代表识别成功。测试结果不准备正式记录时不要保存。

### 3. 语音

在记餐入口录音，说“午餐吃了一碗米饭和一个鸡蛋”。按界面提示结束录音，核对转写与结果。

**通过标准：** 录音权限正常，转写内容基本正确，能继续估算或保存。提示未设置语音模型时，回高级设置检查。

Siri 后台记餐是另一条系统语音入口，见[使用手册](user-guide.md#siri-后台记餐)，不能用 App 内录音测试代替 Siri 测试。

## 失败时逐项排查

| 表现 | 先查什么 | 下一步 |
| --- | --- | --- |
| 尚未保存 API 密钥 | 是否只粘贴而没保存 | 点保存，再测试 |
| 地址必须使用 HTTPS | 是否填了 HTTP 或 Mac 本机端口 | 使用服务商 HTTPS 入口 |
| HTTP 401 | 密钥完整性、所属平台、有效性 | 核对或替换密钥 |
| HTTP 403 | 账户、地区或模型权限 | 在服务商控制台看错误详情 |
| HTTP 404 | 基础地址、协议、模型 ID | 检查重复路径和错误协议 |
| HTTP 429 | 限流或额度限制 | 看平台详情，等待或处理额度，不要连点 |
| 超时、网络中断 | iPhone 能否到达平台 | 同一网络下检查，稍后重试文字测试 |
| 文字能用、照片失败 | 图片模型能力和权限 | 单独核对图片模型，用一张照片测试 |
| 照片能用、录音失败 | 麦克风权限、转写模型和接口 | 核对 iOS 权限及语音字段 |
| 有回答，没有修改记录 | 是否提出可执行建议、对应权限是否开启 | 检查 AI 教练“…”权限，确认建议后查看记录 |

状态码含义以平台实际错误为准，表格是排查顺序，不代表每种错误只有一个原因。

## 配好后还要决定什么

- **自动复盘：** 检查“每天自动复盘并生成次日计划”。开启后会在需要时调用你配置的平台；不想自动产生调用，就关闭。
- **目标自动调整：** “复盘时自动更新当日目标”单独控制，不等于允许教练修改所有记录。
- **建议权限：** AI 教练右上角“…”可选择允许建议修改的内容，应用前仍要核对。
- **备份：** 正常使用时密钥保存在系统钥匙串，完整备份也会包含密钥。删除“本机密钥”不会撤销服务商密钥，也不会清除已有备份；泄露时应到服务商控制台撤销。

最后验收：文字连接成功 → 图片成功（需要时）→ 语音成功（需要时）→ 检查自动调用开关 → 妥善保存备份。
