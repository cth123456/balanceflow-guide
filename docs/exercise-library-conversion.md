# 自己的训练库怎样转换、发布和导入

[返回首页](../README.md) · [完整使用手册](user-guide.md) · [AI 配置](ai-setup.md)

目标是让你完成这条路线：**原始动作数据 → 转换成标准 JSON 数组 → 与媒体一起放到可访问位置 → 取得 HTTPS 原始链接 → 衡动导入 → 检查动作和图片。**

## 先判断是否需要做这件事

- 只想开始训练：用内置基础动作库，无需转换。
- 已有一份动作 JSON，字段符合下面格式：直接准备媒体和链接。
- 已有别的字段或外层包装：用本仓库转换器。
- 只有 Excel/CSV：先导出/整理成 JSON，每行对应一个动作；当前转换器不直接读取 XLSX、CSV。
- 只有 PDF、视频文件夹或某个网站首页：它们还不是动作索引，需要先整理动作名称、ID、媒体路径等数据。

**动作库不是个人训练计划。** 每个条目描述一个动作，不是“周一胸、周二背”的日程，也不是组次完成记录。转换动作库不配置 AI 密钥，不调用 AI 模型。

只使用你有权使用的数据与媒体。JSON 转换不会替你取得图片、GIF、视频的授权。

## 第一步：准备一个动作的标准格式

以下用于展示格式，`example.com` 和媒体文件名均为占位示例，必须换成你真实可访问的文件：

```json
[
  {
    "id": "my-dumbbell-row",
    "name": "单臂哑铃划船",
    "category": "strength",
    "bodyPart": "back",
    "target": "lats",
    "equipment": "dumbbell",
    "image": "images/dumbbell-row.jpg",
    "gif": "",
    "video": "",
    "instructions": [
      "用长凳稳定支撑，保持背部姿势稳定。",
      "按适合自己的负重和活动范围完成动作。"
    ]
  }
]
```

不要删掉最外层 `[`、`]`。两个动作之间用逗号分隔，最后一个动作后面不能有多余逗号；JSON 不支持注释。

| 字段 | 怎么准备 | 缺失或填写不当会怎样 |
| --- | --- | --- |
| `id` | 唯一且长期不变的字符串，例如 `my-dumbbell-row` | 重复 ID 只保留第一条；改 ID 可能影响旧记录匹配 |
| `name` | 可读动作名称 | 缺失可能显示“未命名动作”，不利于查找 |
| `category` | 常用 `strength`、`cardio`、`stretching` | 类型影响单位、分类和计划理解 |
| `bodyPart` / `target` | 部位与主要肌群，例如 `back` / `lats` | 缺失时分类可能退回通用值 |
| `equipment` | 例如 `dumbbell`、`barbell`、`machine`、`body weight` | 缺失可能按自重处理 |
| `image` | 图片地址或相对路径 | 提供静态预览；不是电脑上的本地路径 |
| `gif` | 可选动图地址 | 无动图可填空字符串 |
| `video` | 可选视频文件地址 | 无视频可填空字符串；网站播放器页面不等于视频文件 |
| `instructions` | 字符串数组，每条是一段步骤 | 可选，建议提供清楚的文字说明 |

**远程库每条动作至少需要一项可解析的 `image` / `gif` / `video` 地址。** 无媒体动作会被过滤；转换器输出了条目，不表示它必然会进入 App 列表。地址能解析也不代表媒体文件真实存在，必须再测试能否下载。

### 可以直接导入的字段，与转换器接受的字段不同

App 直接导入的常用写法：

| 含义 | App 接受的常用字段 |
| --- | --- |
| 名称 | `name`、`title` |
| 部位 | `bodyPart`、`body_part` |
| 主要肌群 | `target`、`primaryMuscle`、`muscle_group` |
| 图片 | `image`、`images` 数组第一张 |
| GIF | `gif`、`gif_url`、`animation` |
| 视频 | `video`、`tutorialVideoURL`、`tutorial_video_url` |
| 步骤 | `instructions` 字符串数组，或 `instructionSteps.zh` / `instruction_steps.zh` 数组 |

**不要把 `imageUrl`、`exerciseId` 等源库字段不经转换就直接上传。** Python 转换器识别的别名更多。为减少歧义，发布时使用上面的标准格式。

App 的远程导入需要顶层动作数组。`{"data": [...]}`、`{"exercises": [...]}` 等包装结构应先经转换器展开，不能把转换器支持包装结构误认为 App 直接支持。

## 第二步：用自带转换器整理已有 JSON

这一步需要一台有 Python 3 的电脑。脚本只用 Python 标准库，无需安装额外 Python 包。

### 2.1 下载并准备文件

1. 下载本仓库源码并解压，或使用你已有的仓库副本。
2. 找到 `scripts/convert_exercise_library.py`。
3. 在 `scripts` 目录下新建 `input` 文件夹。
4. 把原始 JSON 复制到其中，命名为 `source.json`。

```text
衡动仓库目录/
└── scripts/
    ├── convert_exercise_library.py
    └── input/
        └── source.json
```

它必须是 UTF-8 文本 JSON，不是把 Excel 文件改后缀成 `.json`。不要把衡动完整备份文件放进这里。

### 2.2 运行

在终端进入下载的仓库目录，先确认能看到 `scripts` 文件夹，然后运行：

```sh
python3 --version
python3 scripts/convert_exercise_library.py
```

Windows 若使用 Python Launcher，可在同一仓库目录运行 `py -3 scripts/convert_exercise_library.py`。

不传文件路径参数，脚本固定读取 `scripts/input/source.json`；没有这个文件时，才尝试读取 `input` 下唯一的 JSON。若有多个候选且没有 `source.json`，先移走多余文件。

### 2.3 看输出，不要只看“没有报错”

输出文件固定为 `scripts/output/exercises.json`，每次运行会覆盖该输出；需要保留旧结果时先另存。

控制台会显示输入记录、输出动作、跳过、重复 ID 和无媒体条数。希望导入 100 个动作却输出很少时，先处理跳过/重复情况；“无可用媒体”不为 0 时，补齐媒体后再转换。

转换器支持顶层数组、单个动作对象，或 `data` / `exercises` / `items` / `results` / `records` 中的数组。常见源字段如 `exerciseId`、`exerciseName`、`imageUrl`、`gifUrl`、`videoUrl`、`steps` 会转换成标准字段。

### 原始数据与输出对照

输入 `source.json`：

```json
{
  "data": [
    {
      "exerciseId": "my-row",
      "title": "单臂哑铃划船",
      "imageUrl": "images/row.jpg",
      "steps": ["稳定支撑，按个人能力完成动作。"]
    }
  ]
}
```

转换后，最外层变成数组，`exerciseId → id`、`title → name`、`imageUrl → image`、`steps → instructions`。类别、器械等没有提供时会补默认值；**默认值不一定符合实际动作**，这个例子仍需把器械修正为 `dumbbell`，补齐部位、肌群，再发布。

字段完全不同，例如 `动作名称`、`照片路径` 时，先手动改成对应标准字段，或让数据提供方按表导出。脚本不理解任意列名，不会自动翻译说明、寻找媒体或把私有地址变公开。

## 第三步：准备媒体和 HTTPS 链接

把转换后的文件和真实媒体一起放到同一可访问目录，例如：

```text
library/
├── exercises.json
└── images/
    └── row.jpg
```

若索引地址是 `https://example.com/library/exercises.json`，其中 `images/row.jpg` 会相对于 JSON 所在目录解析为 `https://example.com/library/images/row.jpg`。

### 用自己的 GitHub 仓库发布

1. 准备仅包含允许分发的动作索引和媒体的仓库。
2. 在 GitHub 文件列表用 **Add file → Upload files** 上传 `exercises.json` 与媒体；保留上述目录关系。
3. 保存提交后打开 `exercises.json`，取得 **Raw / 原始文件**链接；GitHub 页面名称可能随界面变化。
4. 在无痕浏览器打开该链接，确认直接看到 JSON 而非登录页或仓库首页。

```text
文件预览页（不能作为导入地址）：
https://github.com/你的用户名/你的仓库/blob/main/exercises.json

原始文件地址（main 必须替换成实际分支名）：
https://raw.githubusercontent.com/你的用户名/你的仓库/main/exercises.json
```

当前衡动源码仓库是私有的；**不能因为你在浏览器已登录，就假设 App 也能匿名下载其中的文件。** 远程库入口没有 GitHub 登录或自定义鉴权请求头设置。私有仓库应通过自己有权使用的分发方式提供索引，或在授权允许时单独公开不含敏感信息的素材。不要为导入训练库公开个人健康备份、密钥或整个私有工程。

也可使用自有静态网站或对象存储。媒体有权限、签名过期、防盗链、地区限制时，App 也可能无法显示；最好用长期可访问的 HTTPS 文件地址。

## 第四步：在衡动内导入

1. 打开 **设置 → 训练资源 → 接入训练库详细信息**。
2. 将 **当前动作库**切换成 **导入远程动作库**。
3. 在出现的 URL 输入框粘贴 JSON 的 HTTPS 原始地址。
4. 点 **导入或更新此链接**，等待完成。
5. 看“当前生效”“动作数量”和状态/错误说明。
6. 到“训练”搜索至少两个已知动作，打开详情，检查名字、器械、图片、步骤；有 GIF/视频时也分别检查。

**完成标准：** 远程库已生效、数量合理、动作与媒体匹配。不以“按钮点过”“出现加载动画”作为成功。

JSON 字段正确也可能只有部分动作被接纳：重复 ID、无媒体条目或媒体编号保护等会影响结果。若数量异常，抽查被过滤的原始条目。

## 第五步：更新与退出远程库

- 更新同一个 JSON 后，再点“导入或更新此链接”。上传文件到网站不会自动替你刷新 App。
- 保持已有动作 ID 不变；可以修改名称、步骤或媒体。删除/换 ID 可能影响历史匹配。
- 远程模式使用成功导入的远程集合，不会自动把内置库混进来补全。
- 网络失败时会尝试使用已成功缓存的数据；从未成功导入时不要期待有远程内容。
- 想恢复基础库：把“当前动作库”切回“内置基础动作库”，必要时点“重新载入内置动作库”。无需为了退出远程库删除个人训练记录。

## 按症状排错

| 问题 | 检查方法 | 处理 |
| --- | --- | --- |
| 导入 0 条/解析失败 | 无痕打开索引，看是否真是 JSON 数组 | 修正 Raw 链接、去包装，重新转换 |
| 转换器报 JSON 错误 | 查看提示行列，检查引号、尾逗号、编码 | 修正源文件，不能靠改后缀解决 |
| 有输出但 App 少很多 | 看重复 ID、无媒体数量 | 补媒体、去重后再发布 |
| 有名称但没有图片 | 无痕打开该媒体的完整地址 | 检查大小写、目录、权限、防盗链 |
| 视频不能播放 | 链接是否为直接媒体文件 | 不要填视频网站播放页或需登录页面 |
| 图片与动作对不上 | 比较 ID、媒体编号和实际画面 | 修正映射，不要只为通过校验随便改 ID |
| 更新后没变化 | 检查是否更新了相同地址，App 是否导入成功 | 手动更新，查看缓存和网络反馈 |
| 电脑能打开，手机不能 | 用 iPhone 同一网络打开链接 | 检查网络可达性、地区或鉴权限制 |

开始时先用 1–3 个真实动作跑通全流程，再转换整个库。这样更容易判断问题在 JSON、链接还是媒体。
